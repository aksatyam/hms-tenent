01
Design Conventions
The rules every endpoint, event and table obeys

API conventions

  • Base path /api/v1/<module>/…; resources plural, kebab where multi-word.
  • Auth: Authorization: Bearer <JWT>; tenant resolved from the token, never from path/body.
  • Idempotency: Idempotency-Key header mandatory on all money-moving / stock-moving POSTs; duplicate ⇒ original result, same status.
  • Status codes: 200/201 success, 400 VAL-xxx, 409 RULE-xxx / idempotency conflict, 403 entitlement/RBAC deny, 404 disabled-module route, 422 business gate.
  • Pagination: ?page&size, cursor for large sets; all list queries tenant-filtered server-side.

Error envelope

{
  "code": "RULE-PHAR-002",
  "message": "Schedule X item blocked at POS",
  "field": "lines[2].drugId",
  "remediation": "Dispense X drugs only against IPD order",
  "correlationId": "…", "locale": "en"
}

VAL-xxx = field validation; RULE-xxx = business-rule rejection with remediation hint. Localised EN/HI (v1).

Kafka event envelope & outbox

// produced via transactional outbox — atomic with the DB write
{
  "eventId": uuid,
  "tenantId": REQUIRED,   // = Kafka partition key
  "type": "result.critical.alert",
  "version": 1,
  "occurredAt": timestamp,
  "actor": userId,
  "correlationId": uuid,
  "payload": { /* domain-specific */ }
}
  • Outbox: each module writes the event to an outbox row in the same transaction as its state change; a relay publishes to Kafka and marks sent — no lost or phantom events (ADR-05).
  • Consumer rules: idempotent by eventId; re-establish tenant context from tenantId before any DB access; no-op events for a module disabled for that tenant (not DLQ).
  • DLQ: per-topic dead-letter with replay tooling; poison message never blocks a partition indefinitely.

Tenancy & Entitlement — Code Path
The two cross-cutting mechanisms made concrete

Every flow in this document assumes these two mechanisms are already in force (FSD Sec. 3.1). They are specified once here and inherited everywhere; modules never re-implement them.

RLS + SET LOCAL (fail-closed)

-- one RLS policy per tenant table; present in ALL tiers
ALTER TABLE encounter ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON encounter
  USING (tenant_id = current_setting('app.tenant_id')::uuid)
  WITH CHECK (tenant_id = current_setting('app.tenant_id')::uuid);

-- request-scoped; missing GUC ⇒ 0 rows, never all rows
SET LOCAL app.tenant_id = '<from JWT>';
  • A TenantContextFilter resolves data source / schema from tenant_directory and sets the GUC per request.
  • Async workers (Kafka, Quartz, Batch) set context from the event/job header or abort — no ambient access.
  • Break-glass (BYPASSRLS) is a privileged, audited path surfaced in the M09 review queue.

Entitlement guard (service layer ③)

// gateway ① + JWT ② already filtered; guard is layer ③
@RequiresModule("M02")          // ENABLED|TRIAL else 404/403
@RequiresPermission("pos:sell")
public SaleResult posSale(SaleCmd c){ … }

// entitlement read from Redis cache; invalidated on toggle
entitlement:{tenantId}:{moduleId} = ENABLED|DISABLED|TRIAL
  • UI ④ renders nav from the same entitlement set; disabled module unrendered.
  • module.entitlement.changed invalidates the Redis key; all 4 layers refresh within 60 s (BR-NFR-03).
  • Dependency matrix enforced on enable (e.g. IPD requires OPD); core modules never disableable.
Guarded disable algorithm (UC-M12-02)disable(tenant, module): run active-workflow guard → { admitted IPD patients? open POs? unbilled encounters? undelivered reports? } → if any true ⇒ reject, offer read-only grace mode with end-date; else update tenant_modules, publish module.entitlement.changed, apply mid-cycle proration, write audit (actor + reason ≥ 10 chars).
